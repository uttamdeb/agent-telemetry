# AgentTelemetry v2.0.0

AgentTelemetry now has native companions for macOS and Windows. `python3 install.py`
on macOS / `python install.py` on Windows detects the OS and installs/opens the matching
client. Web Settings has a menu-bar/system-tray toggle to launch or quit it, with live
heartbeat status. Open at Login and automatic monitoring remain separate opt-ins.

The Windows tray client uses only Python's standard library and native Win32 APIs.
It shows today's tokens/estimated API spend and monitoring state, provides refresh,
import and startup controls, and opens the full dashboard in the default browser.
It attaches to an existing dashboard or gracefully stops only the backend it owns.
Its branded tray icon opens a native popover with the same layout and content order
as macOS: monitoring switch, Today cards, expandable settings, dashboard button and
refresh/quit footer. It follows Windows theme/DPI settings, supports keyboard and
outside-click dismissal, and scrolls settings on smaller displays. Start-menu shortcuts
also use the app icon. The popovers share controls; Windows uses Segoe UI and opens
the full dashboard in a browser rather than macOS's embedded WebView.

Five macOS defects are fixed: skipped nested signing, previous-value menu figures,
late health results undoing Stop, silently stale connection state, and filters/tab
resetting when refresh cadence changes. The build also avoids the unavailable SDK
State macro; local and CI builds compile the complete app.

Browser windows and both native clients now share one display clock, refresh interval and
serialized usage snapshot. Interval changes propagate in both directions, and refreshing
in either app updates all open clients within about a second plus request time. Manual
continues listening for those explicit refreshes. Cadence changes no longer restart the
backend or reload the embedded dashboard. Native figures represent unfiltered Today;
log parsing retains its separate interval. Older attached backends need an upgrade/restart
for shared refresh support.

Changing cadence during a macOS outage keeps retrying. Windows queued lifecycle
commands honor the latest Start/Stop intent, including Stop during an interval request;
older probes and summaries cannot overwrite a later request.
Closing clients keep their heartbeat alive until the owned ledger save finishes, so
the web toggle cannot launch a competing instance during a slow shutdown.
Windows Open at Login handles paths with spaces and preserves unrelated startup entries;
Open dashboard waits for readiness and respects cancellation during first-run parsing.

The ledger schema remains version 53. Parsing, pricing, archived history and sharing
defaults are unchanged. Native metadata stays separate from usage history, and import
is validated and refuses overwrites. New write routes retain CSRF checks; owned Windows
shutdown additionally requires an unexposed per-process control token.

Validation includes the Python and frontend suites on Linux/macOS/Windows, native macOS
display/lifecycle/navigation reproductions, complete Swift build, local ad-hoc packaging
and signature verification, real Windows popover controls, light/dark render fixtures at
100/150/200% scaling, stale/saving states, branded/numeric icon creation and a Windows
installer check. The render artifacts use invented usage figures. See the CI run for
the exact commit's results; handle creation alone does not establish visual quality.

This is a source release. macOS local installation needs Swift and a macOS SDK; Windows
installation needs standard Python including pythonw.exe. No prebuilt notarized macOS
installer is supplied. Developer ID signing/notarization and Intel package execution
are separate distribution gates and are not claimed by these tests.
