# Local MCP implementation plan

Status: implementing on `feat/local-mcp`, based on main `9674e7a`.

## Research and design decisions

The local data-agent checkout (`faadec4`, `src/lib/mcp/index.ts` and its tool
implementations) demonstrates explicit tool routing, access gates, compact overview
responses, true totals alongside capped details, and registration/bundle parity tests.
Its cloud warehouse, OAuth and internal business rules are not part of this feature.

The local CodeBurn checkout (`2f2a14fb`, `src/mcp/server.ts`, `docs/mcp.md`, and
`docs/design/codeburn-mcp.md`) demonstrates a resident stdio process, cheap usage
queries separated from deeper findings, structured results, bounded output, clear
empty/degraded states, and project-name redaction. We use these design patterns;
AgentTelemetry remains Python stdlib-only and reuses its existing backend snapshot.

The current MCP specification is 2026-07-28. It introduces per-request metadata and
discovery alongside compatibility rules for older initialization-based clients.
Implement and test each advertised version rather than claiming unspecified support.
Sources: [transports](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports),
[tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools),
[legacy lifecycle](https://modelcontextprotocol.io/specification/2025-11-25/basic/lifecycle).

## Architecture

An agent launches `mcp_server.py` over stdio. The bridge uses authenticated,
loopback-only requests to the already-running AgentTelemetry backend. The backend
reads one consistent analytics snapshot, applies the user's MCP scope, and returns
only the requested, allowlisted result. MCP never opens or writes the ledger itself,
starts monitoring, executes a saved server command, changes an agent's configuration,
contacts a model/provider, or invokes destructive dashboard endpoints.

Separate modules own query/filter logic, insight/comparison calculations, MCP tool
contracts/protocol handling, and private access preferences. The query and insight
engines operate on plain snapshots, making their calculations testable without user
logs. Existing dashboard insights should use the same calculations where migrated;
any remaining difference must be documented and tested rather than silently claimed
as parity. No ledger schema change or rebuild is required.

## Consent and privacy

MCP access defaults off. Web Settings shows the warning that tool results can enter
a connected model provider's context. Enabling requires the app's own confirmation
dialog. Separate user-controlled options allow real project/device names and paired
device usage; both default off. Tool arguments cannot expand those permissions.

Private access preferences and random capability keys live in AgentTelemetryNative,
outside the ledger and installation payloads. Consent is bound to the selected local
endpoint and ledger location. Disable/reconfigure revokes or rotates keys. Public
settings, health, usage, sharing, logs, command examples and MCP output never contain
the key. The stdio bridge reads it privately; redirects are refused.

Default output uses stable aliases. Account identities, credentials, session titles,
prompt text, absolute paths, process arguments and saved launch commands are excluded
even when real project/device names are allowed. Source-derived strings remain data.
Both setup UI and MCP instructions/results explain the cloud-context boundary.

## Tool and context surface

1. `get_usage`: totals and daily/multi-dimensional rows by date, project, tool,
   model, provider, IDE and device; date/range and dimension filters, exact-only
   selection, bounded pagination, deterministic ordering and full matching totals.
2. `compare_usage`: current and prior/explicit baseline ranges, reconciled signed
   contributions, partial-period and coverage notes; no causal attribution.
3. `get_insights`: source-aware optimization findings, supporting observations,
   scope and limitations; overlapping estimates are never summed.
4. `list_sessions`: bounded, scoped session summaries with opaque identities,
   date/model coverage limitations and no prompt-derived titles.
5. `get_session_timeline`: existing verified-source metadata events for an opaque
   session identity, explicit missing/archived/remote/truncated states.
6. `get_data_health`: scan coverage, freshness, parser/ledger issues and pricing gaps.
7. `get_catalog`: available dimensions, tools, model/provider vocabulary, scoped
   projects/devices and date coverage, with field and metric definitions.
8. `get_subscription_limits`: existing offline, timestamped quota observations;
   no account identity or live account lookup, and no inferred/refilled quotas.

Static guide/schema resources and investigation/optimization prompt templates explain
how to use the tools. They do not perform model calls or grant additional access.
Every tool has an input schema, read-only annotations and a structured object result
with readable text for compatible clients. Empty, unavailable and partial data stay
distinct. Invalid inputs are rejected; request, response, row and timeline limits
prevent an unbounded context dump.

## Analytics invariants

Dates follow recorded local calendar dates and dashboard filters. Costs retain
dated API-equivalent estimates; subscriptions are not per-token charges. Tokens
are input + output + cache reads + cache writes; reasoning is an output subset.
Tool attribution follows the source, not the model. Copilot exact subsets and other
sources' precision flags must match the dashboard. Account-wide quotas are never
summed across devices/sessions or derived from tokens. Missing historical fields
remain unavailable. Session-list caps and source-timeline limits are disclosed.

## Execution and verification

- Luna query worker: filtering, grouping, pagination, scoped sessions/catalog and tests.
- Luna insights worker: comparison math, optimization rules, evidence and parity tests.
- Luna protocol worker: stdio, tool schemas, client bridge, private access and tests;
  then backend/Settings integration and installation allowlists in a separate pass.
- Coordinator: research, contracts and plan; review each implementation, test protocol
  against independent client behavior where available, inspect privacy boundaries,
  reconcile calculations and run integrated checks. No user agent config is edited.

Tests cover daily totals per project/tool, all filters/precision modes, pagination
reconciliation, archived and partial data, missing/stale quotas, multiple devices,
scope revocation, disabled access, corrupted preferences, secret/path exclusions,
malformed/oversized protocol messages, unknown tools/arguments, version handling,
clean stdout/EOF, unavailable backends and confirmation UI behavior. Fixtures contain
no real ledger or user prompts. Run backend/frontend suites and platform checks;
use CI for macOS checks unavailable on this Windows host. Commit as Uttam Deb only,
push the feature branch and open a reviewable PR. No main push, release or deployment.
